# План: шим Robot API и этап 2.5

## Причина

Админка берёт список роботов из WMS `Robot/GetAll`, WMS проксирует на легаси Robot API
`http://localhost:5143/api/v1/Robot/List`. Порт 5143 на 131 не слушает никто, юнита нет.
WMS отдаёт BadRequest, админка падает в `GetAllRobots` с NRE, список пуст, карта пуста.
В базе робот есть: `Agvs` 98001, `LastNodeId` wa129, `CurrentOrderId` ORD_04330.

## Фаза A. Шим легаси Robot API

1. `GET /api/v1/Robot/List` в нашем API, форма `NTLS.RMS.Definitions.Entities.Agv` (все поля из таблицы).
   Источник: чтение `Agvs` без записи плюс живой `RobotSnapshot` из MQTT.
2. Добавить `GetState`, `GetStateAll`, `GetById` если их вызывает WMS или админка.
3. Переключить WMS `RMS:RobotAPI` на `http://127.0.0.1:5231/api/v1/Robot`, откат одним ключом.

Приёмка A: в админке виден робот 98001, счётчики ненулевые, карта рисует позицию, в логе нет NRE.

## Фаза B. VDA-сессия

4. MQTT-клиент MQTTnet, QoS 1, реконнект, подписка `state`, `connection`, `visualization`.
5. Сборка заказа из `RoutePlanResult`: version 2.1.0, orderId `ORD_<число>`, sequenceId чёт/нечёт, траектория NURBS.
6. Конечный автомат заказа с таймаутами 10 и 15 с, закрытие по `driving=false` и достижению последнего узла.
7. Таблицы `vrt_RobotSession`, `vrt_RobotOrder`, `vrt_RobotOrderNode`, свои миграции, baseline не трогаем.
8. HTTP оператора: `POST /api/agv/{serial}/order`, `POST /api/agv/{serial}/instant-action`, `GET /api/agv/{serial}/state`.
9. Восстановление после рестарта: сессия читается из БД, заказ или продолжается, или безопасно отменяется.

Приёмка B: заказ wa128 → wo-4-9 принимается роботом, доезжает, заказ `Completed` и время закрытия заполнено.
Отмена на середине останавливает робота. Рестарт сервиса посреди заказа не оставляет заказ в `SENT`.

## Фаза C. Совместимость с админкой

10. `POST /api/Order/move-to-node/{serial}/{nodeId}/{dir}` и `POST /api/AgvCommand/{serial}/{command}` в нашей форме,
    чтобы кнопки админки работали без правок UI. Переключение `AgvControlUrl` на нас по команде.
11. Контрактные тесты по снимку `docs/contracts` для этих маршрутов.

## Фаза D. Проверка и вывод

12. Прогон на стенде: смоук списка, заказ, отмена, рестарт, отсутствие записей в legacy-таблицы.
13. Независимая проверка контролёром, затем пуш и короткий runbook переключения и отката.

## Оценка

A: 1 день. B: 6-9. C: 2-3. D: 1-2. Итого 10-15 человеко-дней.

## Что нужно от тебя

1. Окно, когда можно остановить `agv-control-api` на 131: два VDA-мастера на одного робота одновременно недопустимы.
2. Разрешение поменять `RMS:RobotAPI` в WMS и перезапустить его, с откатом по команде.
3. Правило нумерации заказов: продолжаем `ORD_` от максимума в базе или свой префикс.
4. Нужно ли в фазе A обновлять `Agvs` позицией и батареей, или только читать до полного переключения.
