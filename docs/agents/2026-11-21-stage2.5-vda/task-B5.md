# Задача B5: состояние робота через базу

Ветка `ai/stage2.5-vda`, HEAD с моим коммитом про стартовый узел.

## Проблема

Чтение `state` работает в процессе Workers, а HTTP API и сервис заказов живут в процессе API. `IRobotStateReader` хранит снимки в памяти своего процесса, поэтому `GET /api/agv/98001/state` всегда 404, а заказ падает с `NODE_NOT_FOUND`: нет стартового узла.

## Что сделать

1. Писатель снимков: в Workers на каждое событие `SnapshotReceived` сохранять `vrt_RobotSession` (серийник, состояние соединения, последний узел, позиция, батарея, `StateJson`, время). Троттлинг: не чаще одного раза в секунду.
2. Читатель из базы: реализация `IRobotStateReader` с приоритетом память, затем `vrt_RobotSession` (свежесть до `AgvMonitoring:StaleStateSeconds`, по умолчанию 5 с). API должен видеть состояние, даже если писал другой процесс.
3. `GET /api/agv/{serial}/state` и `CreateOrderAsync` используют этот читатель, поэтому стартовый узел находится по `LastNodeId` из базы.
4. Тесты: запись сессии из снимка, чтение из базы при пустой памяти, протухшая запись не отдается, заказ создается по узлу из базы (фейки), плюс интеграционный тест на `rms_vrp_test`.

## Ограничения

- Legacy-таблицы не трогать.
- Миграций не добавлять, таблица `vrt_RobotSession` уже есть.
