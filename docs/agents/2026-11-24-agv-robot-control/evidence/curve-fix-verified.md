# Кривая ребра: проверка на стенде после обновления симулятора

Дата: 2026-11-27. Ветка `ai/stage2.5-vda-port-step3`, коммит `d43e1e1`.
Стенд 131, робот `Tuskrobots/98001`, карта 801.

## Что изменилось

1. Правка в нашем сервисе: `VdaOrderBuilder.BuildTrajectory` передаёт кривую из карты
   (`degree`, `knotVector`, `controlPoints` с весами), а не две крайние точки. Для
   двунаправленного ребра при проезде в обратную сторону контрольные точки разворачиваются
   по тому же правилу, что в AGVControl (`OrderService.cs:1236-1246`).
2. Симулятор на стенде обновлён: старый бинарник был от 13.10.2026, собран из master
   от 27.11.2026 (`ae08603`). Бэкап: `/tmp/bk-simulator-1795795948.tgz`.

## Почему это было нужно

`core/vdalogic`, `src/MotionController/MotionController.cpp:378-398`:

```cpp
if (!edge.trajectory.isEmpty() && edge.trajectory.controlPoints.size() > 2)
    traj = e.trajectory;                // едем по NURBS из заказа
else {
    controlPoints.append(nodeStates[start].nodePosition);
    controlPoints.append(nodeStates[end].nodePosition);
    traj.setControlPoints(controlPoints); // прямая между узлами
}
```

Пока в заказе было две точки, симулятор строил прямой отрезок между узлами и резал дугу.
Масштабирование точек на 100 применяется только при `System/kostil = true`, по умолчанию
выключено, поэтому точки из карты идут как есть.

## Ограничения

- В одном прогоне изменились сразу две вещи: симулятор и траектория. Какая из них решающая,
  отдельным прогоном не разделено. По коду решает кривая: при двух точках симулятор всё
  равно строит прямую по узлам, то есть дугу не видит.
- `HasLoad` в симуляторе не меняется, захват груза подтверждён только статусами действий.
- Проверен один маршрут с одним кривым ребром.
