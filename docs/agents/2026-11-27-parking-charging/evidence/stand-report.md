# Отчёт по стенду: автозарядка и автопарковка

Дата: 2026-11-27. Ветка `ai/charging-parking`, коммиты `031ce78`, `2a2223e`, `b7d79cd`.
Стенд 131, симулятор `Tuskrobots/98001`, карта 801. В карте по одному узлу
`CHARGING` (`ch1`, 14.61/5.19) и `PARKING` (`pa1`, 14.33/35.36).

## Настройки прогона

Секция `Routing:Charging` в `/opt/rms/vrp-workers/appsettings.Production.json`:

```json
{ "Enabled": true, "MapId": "801", "LowerLimit": 20, "TargetLimit": 80,
  "WaitingMinutes": 1, "PollSeconds": 3, "RetryDelaySeconds": 5, "MaxAttempts": 20,
  "PublishChargingCompleted": true, "AutoStopCharging": false }
```

Важно: настройки лежат именно в `appsettings.Production.json`, потому что архив выкладки
содержит `appsettings.json` и перезаписывает его. При первой попытке `Enabled` слетел
обратно в `false`, и триггеры не работали.

## Что было сломано и исправлено по ходу

1. **Фильтр состояний.** Кандидаты на зарядку отбирались только из состояния `Idle`,
   а робот в парковке находится в `Parked`. Разряженный робот в `pa1` не ехал никуда.
   Исправлено: на зарядку допускаются `Idle` и `Parked`.
2. **Освобождение станции.** Робот, зарядившийся на станции, остаётся в состоянии `Charging`,
   а порковочный триггер смотрел только `Idle`, поэтому единственная зарядка была занята
   навсегда. Исправлено: заряженный робот (`Charging` при заряде не ниже `TargetLimit`)
   едет в парковку после `WaitingMinutes`.
3. **Перезапись конфигурации.** Настройки в `appsettings.json` слетают при каждой выкладке.
   Перенесены в `appsettings.Production.json`.

Оба исправления закрыты юнит-тестами:
`TickAsync_ParkedRobotWithLowBattery_GoesToCharge`,
`TickAsync_ChargedOnStation_GoesToParkingAndFreesCharger`.

## Что на стенде проверить нельзя

На стенде один робот и по одному узлу каждого типа, поэтому не проверены живьём:

- конкуренция двух роботов за одну станцию;
- выбор из нескольких станций и парковочных узлов;
- приоритет по заряду и тай-брейк;
- ожидание, когда все станции заняты.

Эти сценарии закрыты юнит-тестами `RobotRelocationServiceTests` и
`RobotRelocationWorkerTests`. Для живого прогона нужен второй робот в симуляторе
и второй узел `CHARGING`.

## Замечания

- Симулятор не выставляет `batteryState.charging = true` при зарядке, в БД `IsCharging`
  остаётся `false`, хотя заряд растёт. Поэтому состояние `Charging` определяется по узлу
  под роботом и заряду, а событие `agv-charging-completed` срабатывает по пересечению
  `TargetLimit`. На реальном роботе поле нужно проверить отдельно.
- `HasLoad` в симуляторе не меняется, к этой задаче отношения не имеет.
- Параметр `ChargerId` по умолчанию `20373` взят из конфигурации AGVControl. Для карты 801
  значение стоит уточнить у эксплуатации, на движение и на событие оно не влияет.
